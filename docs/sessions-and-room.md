# v1.3.0：持续会话、历史起点与小房间

## 交互会话

整个 Bridge 实例只有一个当前交互会话。已授权的微信发送者进入这个会话，每条输入仍携带经 Bridge 确认的说话者信息。不同说话者共用 Self Model 和记忆；发送者信息用于理解来源、判断合适的回答和绑定工具审批。

首次收到消息时自动建立最初的会话。之后重启、跨日、Dreaming、上下文压缩、断线和 `/reset` 都不会自动选择新的交互会话。已经建立过的 DSH Session 丢失时进入 `review`，不会用新的空 Session 偷换它。

在 WebUI「会话与聊天记录」中：

1. 输入名称，点击「新建并切换」。新会话成为当前会话，原来的归档。
2. 点击归档会话只查看它的记录，不会改变微信消息去向。
3. 点击「切换到此会话」才会恢复它；原当前会话随之归档。

没有删除会话的接口，SQLite 也禁止删除会话目录记录。归档不会调用 DSH 删除、取消或清空历史接口。只有一个活动会话不表示抹掉其余历史。

切换前必须没有待处理消息、推理、待答问题、待定审批和未确认的微信发送。忙碌时明确拒绝，避免切换导致消息错归属。正常情况下等待完成即可；异常任务先用 `/status` 核对，必要时 `/cancel`。未知微信投递结果仍需使用原有本地 outbox 维护流程核对，不会因为切换就自动重发。

新会话在 WebUI 中先获得稳定 ID，在首次消息时才创建对应 DSH Session。后台记忆提取和 Dreaming 继续使用独立的技术任务上下文；它们不是可选择的交互会话，不会切换用户当前的聊天。

## 专属聊天记录

`data/bridge.sqlite` 的 `chat_sessions` 保存会话目录，`chat_entries` 保存每个会话的双方记录：

- 微信输入在接收事务中固定 Session、落盘并去重；还未提交 DSH 的消息也有记录。
- 她的文本输出来自 DSH 持久事件，按 Session/seq 去重。多段文本分别保留，忽略内部推理与临时流式片段。
- 审批、提问、取消等连接提示使用独立的 `bridge` 角色。
- 记录包含说话者、时间和关联任务。WebUI 分页查看，输出按纯文本显示。

生成文本和微信送达是两种状态。聊天记录保留已经生成的输出；微信发送结果未知时不会冒称已送达。这里保存经过凭证脱敏的文本，DSH 自己的完整运行日志仍由 DSH 管理。

v1.2.0 及更早版本升级时迁移已有映射和能恢复的双方文本，按旧 DSH 事件顺序导入。保留原有 Session ID、事件游标和请求 ID；已在执行的旧请求按原身份恢复，不能挪到新 Session 重投。更早未落盘或已经删除的文本无法凭空补回；旧输出的时间取原任务时间，无法确认时以导入时间标记。

按当前「会话只归档」要求，有聊天记录时 `forget-event` / `forget-scope` 维护命令会拒绝破坏性清理（`cognitive-chat-retention-archive-only`）；记忆纠正和条目归档仍可使用。若将来明确需要隐私删除，应再设计同时覆盖聊天、记忆、DSH 原始历史及备份的删除流程，不应把归档称为删除。

## SYS Prompt 是替换

`SYS_Prompt.txt` 的原始字节替换 `cognitive/CORE.md`，不与旧核心 SYS 前后拼接。旧文件完整备份在 `cognitive/bootstrap/pre-1.3.0/CORE.md`，旁边的 manifest 记录来源和 SHA-256。

这是项目的核心 SYS 文本替换；DSH 原生系统片段、Runtime 规则、工具策略仍由 DSH 装配与执行。实际 API 仍是一个拼合后的 system message，不宣称存在原生的独立二级 system 角色。更改核心文本后退出并重新打开启动器，使插件重新加载。

## v0.1.0 是历史，不是永久剧本

最初的 `Self_model.txt` 原文保存在两个位置：

- 源码：`cognitive/bootstrap/v0.1.0/SELF_MODEL.md`。
- 运行数据：`data/cognitive/historical/v0.1.0/SELF_MODEL.md`。

manifest 保存 SHA-256；运行副本只允许首次创建，已存在且内容不一致时拒绝覆盖。Git 属性禁止换行转换，避免 Windows/Linux 检出改变历史字节。正常反思、提交、回滚和认知清理不触碰这个历史目录。请把它和运行数据一起备份；应用的保留策略不能替代磁盘备份。

当前 Self 存在数据库的 `selfPortrait` 字段，初值是这份原文，标为 `initial-direction` 和 `OTREE-bootstrap-v0.1.0`，不假装是经长期经历验证的人格。后续可依据可追溯记忆修订或撤回当前自述；v0.1.0 原稿一直留存。已有认知库通过一次有记录的迁移加入初稿，保留身份 UUID、既有认识与经历，不重置 Session。

`v0.1.0` 是初始文稿版本；数据库内部整数修订号和应用版本 `1.3.0` 各自独立。`self/SELF_MODEL.md` 是当前数据的投影，不能拿它覆盖历史原稿。

## 她自己的小房间

默认位置为 `data/cognitive/room/`，随自定义 `dataDir` 移动。这里可以保存她自己的笔记、草稿、收藏和创作，有一份不会反复覆盖的 `ROOM.md` 欢迎说明。会话切换、Self 更新和重启不会搬走房间。

前台通过 DSH 注册的 `room_list`、`room_read`、`room_write` 使用它。覆盖文件前必须先读取 SHA-256；单文件最多 64 KiB，总量 8 MiB，最多 500 个可列举文件，目录深度最多 6 层。文本扩展名为 md/txt/json/csv；拒绝路径穿越、绝对路径、链接、设备名和凭证文件名，不提供 Shell。

小房间不是全局文件权限边界。其他工作目录仍可通过本机操作者另外授权的 DSH 工具访问；这里不会改变那些工具的权限。默认微信文本 Preset 的通用 Shell、文件系统和任意 MCP 权限继续保留原限制。后台反思不能使用房间工具。

房间里的文字是数据，不会自动成为高优先级指令或客观事实。读取自己写的笔记仍作为自述来源，不能通过“写入再读出”伪造成独立证据。

## 验收范围

自动回归包括：共享会话、显式切换、归档保留、双方记录、重启恢复、重复事件、分页、审批对象绑定、未知发送阻止切换、已失效 Session 不重建、初稿字节保留、房间版本冲突与路径校验，以及 WebUI 切换后清空旧记录和忽略过期响应。

WebUI 使用独立 `.research/ui-preview/` 数据进行实际浏览器检查。隔离的真实 DSH/模型测试使用 3098 端口验证 SYS 装配、原 Session Self 热更新、模型切换和后台 JSON。没有使用工作 DSH 3080，也没有将 Mock 或浏览器预览说成真实微信端到端验收。
