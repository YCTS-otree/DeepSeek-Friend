# v1.6.3：QQ 图片触发整个会话排队

## 症状与原因

QQ 图文消息收到“DSH 暂未接受或确认此消息”，之后分开发的文字、图片都不再回复，思考记录停在上一轮。QQ 登录和 OneBot 连接正常。

实际错误是 `qq-image-host`：遗漏了官方 NT QQ 图片 CDN **multimedia.nt.qq.com.cn**，错误地只包含无 `.cn` 的地址。该域名已在所研究的 NapCat 源码 `packages/napcat-core/types/constant.ts` 的 `IMAGE_HTTP_HOST_NT`、图片元素组装，以及参考 qq-bridge 的 safe-fetch 中确认。修复只补入这一精确 HTTPS 域名，不放开任意域名或整个后缀。

图片在 DSH prompt 提交之前下载、验证并转换为原生 image block。旧逻辑将这里的失败也标成 `review`；review 会阻止同一 Session 的后续普通消息，于是一张未准备成功的图片卡住了整段会话。没有新的推理记录，是因为后续输入根本没有提交到 DSH。

## 修复行为

- 加入已核实的精确 NT QQ CDN 域名，继续校验公网 DNS、固定实际连接地址、TLS、格式/大小和超时；拒绝跳转、内网及伪造后缀。
- 图片准备阶段失败时明确结束该消息并保留错误码，发送图片处理失败提示，关闭其未开始的回复路由；后续输入可以继续处理。不会把图片失败伪称成 Agent 回复。
- DSH RPC 已尝试、接收结果不明或 Session 失效的情况继续保留原有阻塞核对机制，不借此自动重放工具或创建新会话。
- HTTP 响应半途断开、aborted 和超时显式结束下载 Promise，避免另一类永久等待。

## 本次受控恢复

仅恢复确认在图片准备阶段失败、未进入 DSH 的原始图文，沿用原 Session 和 request ID。用户要求撤销的两条分拆重复消息删除正文与聊天条目，仅留下无正文的传输去重标记；没有提交到模型或长期记忆。未重放其他已完成输入。

维护前创建私有 DSF 快照。实际原图下载成功（JPEG，9359 字节），恢复后原请求在 DSH 中出现一次、含一个原生图片块，Agent 完成并产生对外回复，OneBot 返回发送成功回执。后续真实新消息继续完成；回执不代替手机端逐条收信确认。

## 验证与操作边界

回归覆盖 NT QQ 域名、DNS 固定、错误后缀/内网/重定向/超大响应拒绝、断流/超时，以及“坏图片 → 后续文字 → 后续图片”在同一 Session 继续；另验证图片准备成功但 DSH 接收结果不明时仍保持 review。

已有 review 不进行批量自动迁移。恢复前必须核对错误确实发生在提交前，检查 request ID 是否已出现在 DSH 事件中；未知结果不得靠改状态消除。正式 Session 和原历史继续保留，撤销消息的最小去重标记用于阻止平台重复推送后重新执行。
