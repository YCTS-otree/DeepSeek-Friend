# v1.4.1：旧会话工具全部延迟加载导致 Agent 异常

日期：2026-10-23。

## 原因

当前正式会话此前以空工具目录开始。v1.4.0 修复 Preset 工具可见性后，DSH 0.2 的 addition-only 投影将后来新增的工具标为 defer_loading=true；原基线没有立即可用的工具。DeepSeek 实际拒绝请求，返回 INVALID_REQUEST：tools: at least one tool must have defer_loading=false. All tools cannot be deferred.

此前新会话的真实模型测试通过，因为它从首次请求就带完整工具目录；它没有覆盖这个旧会话升级路径。这是本项目的兼容测试遗漏。

## 修复

前台插件在原生 agent/pre-step 检查 Session 的 toolHistory() 与当前可见工具。若原基线在当前工具集中没有立即可用项，而本轮有正常立即可用的工具，返回原生 startsRequestSeries:true。DSH 据此写入新的声明基线，保留原 Session、原消息、原始事件、Self、记忆与权限。

这里的 request series 是模型请求声明基线，不是新的 DSH 会话。不修改 DSH 核心、不重建会话、不伪造工具调用、不授予新权限；基线建立后正常步骤不再重复重建。旧立即加载工具被移除、剩余全是新增工具时也使用同一兼容处理。

此外，模型失败完成时保留经过格式校验的错误码，status 和 WebUI 能查看，避免 turn/end 把异常覆盖成没有错误的 done。服务端错误正文、正文中的凭证和内部思考不进入状态日志。

## 验证

- 隔离 3098 / 研究 home 使用测试插件，通过 DSH 原生事件创建“已有空工具基线”的历史；仅匹配独立测试 Session 前缀，正式部署不加载此夹具。
- 加补丁前真实 Flash 测试复现 turn/end error，无正常 assistant 输出。
- 补丁后同一类历史在原 Session 成功调用两次消息工具、识别图片、记录 low reasoning 并同轮继续运行；两项真实模型用例通过。
- Node 124 项：121 通过、3 项真实环境开关用例跳过；Python 20 项通过；JS 语法检查通过。
- 单元测试覆盖空基线、移除旧工具、已有有效基线、新 Session、下游拒绝、消息对象保持原样，以及失败错误码可见但正文不泄露。
