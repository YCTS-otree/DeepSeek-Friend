# v1.6：QQ Bot、首页扫码与收藏表情

## 部署与首页

保留项目已有 Node 24、Python 3.10+ 和独立 DSH。Windows 项目内安装：

```powershell
npm run qq:setup
.\start-web.bat
```

安装器经代理 `http://127.0.0.1:10808` 下载官方固定版本 NapCat `4.18.41`，先校验 SHA-256，再安全解压至 `.runtime/qq-gateway/4.18.41`。可用 `python scripts/qq-setup.py --archive "路径\NapCat.Shell.Windows.Node.zip"` 安装已下载的同一归档。未安装时一键启动仍可使用微信；QQ 按钮会提示先安装。不会自动安装系统 Python/Node，也不会修改已有桌面 QQ。

网关自带 Node 22.11.0 是其原生 QQ 库要求的应用内运行时；Bridge/DSH 仍使用项目原有 Node 24。当前安装包仅适用于 Windows；Linux 保留连接外部本机 OneBot 的方式，不冒称此 Windows 原生包支持 Linux。

首页两张授权卡片分别显示微信与 QQ 二维码，使用对应手机应用扫描。下方 **02 / 服务控制 → 一键启动全部** 启动独立 DSH、微信 Bridge 和已安装的 QQ Bot。QQ Bridge 在网关完整登录后自动连接；四项状态独立展示，Bot 进程运行不等于已连接消息通道。停止按钮结束启动器自己启动的服务，不按端口杀死无关进程。QQ 卡片也可单独启动/停止网关和刷新二维码；「QQ 与通讯录」保留外部 OneBot 高级配置。

手机端自行处理扫码冷静期（用户确认为约 5 秒）。网页和管理器不添加额外倒计时、人工等待或刷新拦截；直接显示网关返回的扫码、等待确认、初始化和登录完成状态。只有 `isLogin && coreReady` 才显示成功。二维码过期仅在未扫码状态下自动刷新，不在等待确认或初始化时自动换码；操作者可以按需手动刷新。验证码、设备验证或 QQ 风控需在官方手机端处理。

若原生网关返回“当前账号已登录，无法重复登录”，明确显示账号占用，不能当成已授权或隐藏为冷静期。先退出该机器人账号的桌面 QQ，再刷新二维码；其他 QQ 账号无需退出。QQ 登录与后续 OneBot 配置独立报告，通道配置失败不会把成功登录误报为未登录。

QQ 卡片直接显示网关/API 的原始错误提示，并保留稳定错误码；Token、Cookie、密码、授权头及带凭证的链接等先脱敏，最多 2000 字符，以纯文本渲染。该详情只存在于专用进程 IPC/启动器内存和认证控制台，不进入运行日志、DSH Prompt、聊天记录或长期记忆。正常状态恢复后清除当前提示。

## 权限与运行数据

网关 Web API 只监听 `127.0.0.1:6101`，OneBot 正向 WebSocket 只监听 `127.0.0.1:3001`。管理器只访问固定本机地址和有限 API 白名单，拒绝重定向。端口已有程序时拒绝接管。授权后保存机器人 QQ 号供原生快速登录；微信和 QQ 不会因此新建正式 DSH Session。

Web 管理 Token、OneBot Token 经项目凭证层保护，Windows 使用当前用户 DPAPI；不得把凭证文件发给他人。NapCat 运行必需的私有配置保存在受保护的 `data/qq-gateway` 下；其中上游要求的 WebUI Token 是配置明文，故整个目录都应视为敏感数据。该目录、凭证、原生缓存和 QR 不进入 Git/发布包或 DSF 白名单。原生进程原始输出不进入控制台日志，二维码通过经过验证的专用 IPC 和受认证的图片接口显示。

网关进程不继承 DSH API Key，只传递运行必需环境变量。原生客户端的数据目录行为仍受 QQ/NapCat 版本影响，不保证其所有原生文件都由环境变量完全隔离。请始终用原 Windows 用户启动，避免 DPAPI 解密失败。

## 图片与收藏表情

DSH 原生交互插件增加四个工具，现有会话通过原生请求声明更新工具目录：

| 工具 | 用途 |
| --- | --- |
| `qq_sticker_list` | 列出当前已同步的收藏表情、说明及不含远程地址的 ID |
| `qq_image_view` | 查看已接收图片或收藏表情；返回 DSH 原生图片块，由 4.1 Flash 识别 |
| `qq_send_sticker` | 向明确的 QQ 好友 recipient 主动发送收藏表情或已保存图片 |
| `qq_sticker_add` | 将已接收/已保存的图片加入当前 Bot 账号收藏 |

不必先收到好友消息才可以主动发给现有好友；具体对象从通讯录/联系人 ID 选择。昵称不会授权 QQ 身份。仍只接受现有好友私聊，群/陌生人不接入。接受/发送好友申请目前未实现；编辑通讯录也不会添加好友。

收藏通过 `fetch_custom_face_detail` 每分钟同步，当前最多前 100 项，图片按需下载。收到的图片也使用原生 DSH 图像输入，不生成虚假文字识别结果。下载仅允许明确的腾讯 CDN HTTPS 域名，校验公网 DNS 并固定连接地址；不跟随重定向，有大小/超时限制，且校验 PNG/JPEG/GIF/WebP 实际格式。工具不接受任意 URL 或任意本机文件路径。

发送与收藏操作先持久化。发送超时/断线及收藏结果不明被保留为 `unknown`，不盲目再次执行；OneBot echo 只是请求关联，不冒充服务端幂等键。重启把在途收藏标为未知；再次提交同一待定图片不会绕过去重。测试空间不能读取正式收藏或发送/收藏真实 QQ 图片。

当前覆盖普通图片和收藏表情，不承诺完整 QQ 商店表情包、原生付费表情、语音/视频、动态图像的全部动画语义或收藏分页超过 100 项。共享 Self/记忆保持原有模型判断披露的边界，未新增跨用户分库。

v1.6.3 补齐官方 `multimedia.nt.qq.com.cn` 图片域名。图片准备失败会结束该条并明确提示，不再卡住同一 Session 后续消息；DSH 接收结果不明仍保持受控核对。断流与超时不会留下永久下载等待，详见 [故障修复记录](incident-qq-image-queue.md)。
