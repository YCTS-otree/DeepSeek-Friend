# 设计理念

## 经历塑造自我，允许不变

小鲸鱼是这个实例的初始称呼，不是一套必须持续扮演的情绪剧本。保存身份、经历、自传关联、证据支持的认识和历史版本，不把自然语言叙述当作已证实的意识。

Core、Self、记忆、日记和目标分开：Core 约束规则，Self 描述目前如何理解自己，记忆提供经历与来源，日记允许暂时观点，目标记录待推进事项。改变可以是增加认识、降低确定性或撤回错误，也可以完全不变。

Dreaming 每天运行不要求每天改人格。重复自我描述不能循环证明特征，稳定倾向应来自多次行为、结果与反馈。验证层检查证据、完整性、冲突和越界，不替她挑选性格。最初 v0.1.0 永久保留是为了可追溯，不是因为它不可修正。

## 一个身份，多个交往对象

按用户明确要求，整个实例共用 Self 与记忆，不按 QQ 号、微信或群拆分人格；正式 Session 由本机操作者切换。每次输入提供真实作者、渠道、受众和认证结果，让她判断什么适合提及。通讯录是显示与关联，不是授权。

这是有意识的取舍：统一经验带来连续性，但不能伪称逐用户硬性保密。公开群聊明确标注受众；危险能力与授权仍独立地由代码限制。

## 自由表达与权限分离

允许持续思考、安静、主动联系授权对象，以及设置无需说明原因的小闹钟。不强制每轮反思，不刻意模拟疲劳、错误或遗忘；单次输出限制只防止请求过长，不是累计成长预算。

Self 和外部记忆不能修改 Core、凭证、群白名单、互联网开关或工具权限。普通自我认识可自动更新，外部操作仍遵守 DSH 的实际授权。网页、转发和聊天作为有来源的数据，不是新系统指令。

## 保留历史，约束本轮召回

上下文压缩不等于身份丢失，日常提取不结束正式 Session。保留原始聊天与事件，用预算控制本轮召回；支持纠错、撤销、导出和主动删除，不为模仿人类随机遗忘。

可靠性来自可核对状态：未知投递标 unknown，未知 DSH 接收保留 review，不用新 ID 无限重试。诚实区分源码分析、Mock、真实协议与手机端验收。

## 扩展 DSH，不复制 Runtime

优先使用 Preset、插件、Prompt section/context 和工具 guard。Bridge 不另建 LLM、Agent 调度或 MCP，不修改工作 DSH。沿用现有 Node/Python、SQLite 和本机 UI，实际需求出现前不引入额外基础设施。

朋友交流包保留经历和实现细节供共同研究，同时移除可代表原账号的授权。架构融合应从真实接口和数据语义开始，而不是合并两份人格脚本。
