# DSF v2：DeepSeek:Friend State

`.DSF` 使用 ZIP 容器，内部唯一 manifest.json 声明 `format=DeepSeek:Friend State`、`schemaVersion=2`、createdAt、appVersion、dshVersion、`credentialsIncluded=false`、components 组件格式表及每个文件的相对路径、字节数、SHA-256。

归档范围使用代码白名单：应用 bridge.sqlite、interaction.sqlite、cognitive、testing、media；项目独立 DSH 的 sessions、attachments、llm-deepseek/files-v3.json；当前 SYS_Prompt.txt 和 cognitive/CORE.md。SQLite 通过原生 backup API 保存一致数据库，原生 Session 日志保留压缩文件原样，不自行重构另一套 Agent 上下文。包括双方历史、原生上下文、统一记忆/Self版本、小房间、通讯录和运行设置；不包含程序、依赖、签名私钥、API Key、微信/QQ/DSH登录凭证或整个 DSH home。原始 Self v0.1.0 的源码历史永远保留，不因恢复覆盖。

归档有私密对话和模型本机思考，**不是加密格式**。默认保存在项目 Archive，Windows 使用已有安全目录 ACL，Linux 目录仅用户访问；请妥善保管，不上传公开仓库。

## 创建与回滚

先在 WebUI 停止服务，确认独立 DSH 3088 和 Bridge 都已停止，再在项目目录运行（Python 3.10+，无需新依赖）：

```powershell
python scripts/dsf.py create
python scripts/dsf.py inspect "Archive/实际文件名.DSF"
python scripts/dsf.py restore "Archive/实际文件名.DSF" --confirm-restore
```

默认输出 `Archive/YYYYMMDD-HHMMSS-随机标识.DSF`，不覆盖已有文件。v1.9.0 控制台「DSF 归档」支持创建、下载、完整校验、备注、移入回收站及还原备份；不提供永久删除。网页创建/回滚会停止本启动器持有的 Bridge 和独立 DSH，完成或失败后恢复原来运行的服务；不接管外部服务。保存/恢复全过程持有与 Bridge 相同的 instance-lock.sqlite 排他锁，拒绝正在监听的独立 DSH。命令行操作前仍需停机；外部绕过锁启动服务不在格式保证范围。当前仅允许项目内部数据目录，不对外部路径执行恢复。

## 三次独立确认

网页点击某份备份的「核对兼容性并回滚」，先核对各类数据的独立版本兼容报告，再依次展示目标核对、覆盖范围、保存当前状态三个确认阶段。每次提示出现后按钮至少禁用 3 秒，服务端也以单调时间检查每一阶段；即使修改前端或直接发请求也无法提前完成。各阶段使用一次性 nonce、固定目标摘要和 15 分钟有效期，过期、取消、重复确认或目标文件变化会停止操作。第三次确认后才开始停机、保存当前状态并完整校验，再恢复选定备份。当前备份失败或校验失败均不替换数据。

CLI 的 `--confirm-restore` 也要求交互终端中的三次确认，每次强制等待 3 秒；参数不再等同于跳过确认，不接受管道自动输入。内部恢复函数供通过网页三次校验的管理器调用。服务端固定整份快照的组件清单与迁移计划，确认请求不能缩小范围。CLI 也先展示完整恢复范围并固定文件摘要。

## 独立格式兼容、整份恢复 · v1.11.1

`schemaVersion` 表示容器格式，`appVersion` 仅表示创建程序版本，两者不是数据组件版本。v1.11.1 读取 v1/v2；v1.10.0 及更早程序不能读取新 v2，需先更新读取器。

| 组件 ID | 内容与契约 |
| --- | --- |
| `dsh_context` | 原生 Session、附件、模型文件索引；目前保守要求相同已检测 DSH 版本。未知运行时需先核对，不假定日志兼容 |
| `bridge_state` | 通道游标、聊天记录、会话映射、媒体，`bridge-state/1`；随完整快照恢复，避免身份和队列错配 |
| `cognitive_state` | 统一长期记忆、Self、版本、日记与目标，`cognitive-state/1`；当前共享数据库，作为原子组恢复 |
| `room` | 小房间文件，`room-files/1`，独立格式契约，不受 DSH/应用版本影响 |
| `prompts` | SYS_Prompt.txt 与 cognitive/CORE.md，`prompt-files/1`，独立格式契约 |
| `test_state` | 测试记忆与资源，`test-state/1`；不等于全部测试聊天/原生 Session，后者在上下文/桥接组 |

例如创建程序是 1.9.1，而当前程序是 1.11.1，只要各类数据格式仍相同，整份快照就能恢复。DSH 一直保持已核对的相同版本/日志格式，上下文契约无需变化。假设后来只有记忆架构从 `cognitive-state/1` 升为 `/2`，兼容报告应显示上下文、小房间等“兼容”，记忆显示“恢复时迁移”；只调用记忆迁移器，然后一起恢复整份快照。

这不是让用户分别恢复各类数据。网页是只读兼容报告，没有恢复范围勾选；CLI 也不提供 `--components`。所需迁移器缺失时停止整次回滚，补充迁移器后再恢复，不能默认跳过记忆而混合两个时间点。新格式没有转换路径只代表尚缺迁移步骤，不代表旧快照永远不能使用。

各组件的格式版本只在该组件的持久化结构发生不兼容变化时更新，不跟随应用的 MAJOR/MINOR/PATCH。Self Model 内容历史版本（如 v0.1.0）也不等于其存储格式版本；普通 Self 演化无需提升快照组件格式版本。

旧 v1 缺少组件表，读取器按白名单路径推断实际存在的组件，非 DSH 组件记为 legacy revision 0。内置 `legacy-v1-component-metadata` 迁移只补充格式识别，不重写归档或数据。原 v1 文件、摘要与创建时间保持不变。此识别仅适用于本项目既有 v1 白名单布局，不保证任意第三方同名数据库可用。

未来架构变更在 `scripts/dsf_compat.py` 注册组件专属迁移，允许多步寻找转换路径。迁移器来自可信程序代码，不能来自归档。先提取整份快照到临时目录，只对格式变化的组件运行其迁移器，校验完成后再替换当前数据；兼容的组件不执行转换。失败保留现状。未提供迁移器时显示“需要迁移”，停止整次回滚，待适配完成后再恢复。目前尚无 DSH 跨版本日志迁移器；新增 SQLite/认知格式时必须同步更新其契约版本和回归。

只读检查与整份恢复示例：

```powershell
python scripts/dsf.py plan "Archive/实际文件名.DSF"
python scripts/dsf.py restore "Archive/实际文件名.DSF" --confirm-restore
```

所有回滚仍先保存并完整校验当前完整状态，然后恢复快照覆盖的完整状态；网页三次独立确认每次至少 3 秒不变。正式状态不用于回滚测试，服务暂停期间不会为检查自动启动 DSH。

## 大功能开放前的检查点

本机控制台扩大互联网白名单/开启互联网测试、启用新 QQ 通道或新群时，经 Python `ArchiveManager.feature` 集中入口先创建并完整校验 DSF，归档完成后才应用设置。关停和相同设置重复保存不强制再备份。处理会短暂停止通讯，QQ 不保证重投维护期间未被 Bridge 接收的消息。归档保留 reason 字段，缺少该字段的旧归档显示 legacy。

项目 AGENTS.md 要求所有后续重大信息来源和能力开放接入这一检查点；不能把新增开关绕过该入口。当前互联网仍仅供本机操作者测试，不向 Agent 注册访问工具，创建备份本身不是开放互联网的授权。

回滚前先校验格式、兼容版本、清单、SHA-256、路径、重复文件、符号链接与大小限制，且自动生成一份恢复前状态 `.DSF`。仅替换白名单组件；顶层数据库旧 WAL/SHM 一并隔离，原生派生投影缓存清除后由 DSH 从恢复的日志重建，凭证原地保留。应用阶段异常会将已移动组件还原；断电等无法执行异常回滚的情况应使用恢复前归档重试。此为多组件受控恢复，不声称文件系统跨目录事务。

归档只含状态；**应用版本不同不会阻止恢复**。恢复条件依据各组件格式契约；未知格式不执行未经验证的数据库跨版本降级。跨机器迁移仍需重新登录与配置 Key；原生上下文中的绝对路径及外部工具环境未保证可迁移。校验和用于损坏检测，不能证明归档来自可信作者，不要恢复陌生来源归档。

测试覆盖合成聊天/原生上下文/房间的归档与回滚、恢复前备份、凭证路径排除、篡改拒绝、目录穿越拒绝、组件不兼容与运行中锁拒绝。新增逐阶段不足 3 秒拒绝、nonce 重放、取消、目标变更、备份失败不恢复/不开放功能、HTTP Cookie/Origin/CSRF、下载鉴权、回收站还原及真实启动器工作队列互斥。浏览器使用独立测试目录完成三次确认和实际回滚，并核验恢复前 DSF 存在。正式数据只做创建和完整校验，不执行回滚测试。

## 空闲归档压缩 · v1.10.0

启动器每分钟检查一次：当会话至少 5 分钟没有任务活动且无排队/进行中任务、回滚确认或维护操作时，单个后台线程尝试处理一份保存满 24 小时的归档，优先处理最旧文件。使用 Python 标准库 ZIP LZMA 压缩，仍是可直接校验和恢复的 .DSF，无需另外解包外层文件。原清单、文件摘要、创建时间、应用版本及备注保持。

压缩写入同目录独立临时文件，完整校验后仅在更小时原子替换。变大则保留原文件；新任务或前台备份操作会令压缩让步，中断不替换原文件。已经全部采用 LZMA 的文件跳过。原生 zstd 等内容不保证还能缩小；断电可能留下不被列表识别的 .compressing 临时文件，原 DSF 保留。回收站内备份暂不压缩。

列表及回收站每条显示“1分钟前 / 1小时前 / 1天1小时前”等相对时间，并保留完整本地日期。相对时间基于原始创建时间，不会因压缩而变年轻。损坏文件缺少创建时间时使用文件时间。
