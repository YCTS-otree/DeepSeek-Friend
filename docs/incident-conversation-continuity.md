# 事故记录：保住原始记录不等于保住认知连续性

日期：2026-10-25。影响版本：DSF 1.13.0 / MNN 1.2.1。修复版本：DSF 1.13.1 / MNN 1.2.2。

## 观察与原因

用户发现维护后的两次回复与此前的对话风格明显不同。检查确认，两次消息都进入原正式 Session `ea38d96b…`，没有新建会话；路由、底层 Flash 模型、SYS、版本化 Self Model 均未切换。原始聊天与 DSH 事件仍然存在。

原因是隐私修整过度：旧的 `privacy_prepare` 把非系统活动 Surface 全部分段替换，只保留稀疏的长期记忆索引和有限证据，没有保留近期正常对话的原话及相处语境。它通过了“原始前缀、身份、指令、压力、安全边界”验证，却没有验证模型真正可见的日常对话连续性。

这是实现和验收缺陷，不能用“原 Session ID 没变、数据库没丢”判定认知上下文完好。模型回复中对自己为何这样说话的解释，也不是可靠的运行时诊断。

## 架构经验

在本项目的记忆—自我驱动架构下，记忆并非仅供查询的知识库。模型当前可见的经历、双方的原话、关系和话题线索，会参与塑造当下的行为、表达与相对稳定的倾向。Self Model 不变，不能保证表达自然连续。

因此，维护必须同时保护：原始历史、有效活动上下文、当前目标、相处经历和长期记忆的可检索性。不能把“存着、可查到”当成“当轮能够自然使用”；也不能把维护造成的突然变化误写成 Agent 自发的成长或偏好演化。

修复应恢复有来源的经历，不应增加“必须像以前说话”的人格指令。短期表达改变并不单独证明稳定人格已永久改变。本次记录是一项有证据的工程观察，后续需要继续实机验证。

## 修复

- MNN 新增有预算的 `recent_dialogue`：按完整对话单元选择真实用户输入与 Agent 文本，保留时间、说话方、来源序号及原话。
- 常规 Dreaming 和隐私重建均保留这一层，不能只留下主题标题。
- 排除诊断轮次、运行时模板、reasoning、私密笔记和失败/结果不明的发送。工具回复仅保留确认已排队的文本，明确不冒称送达。
- 媒体保留来源提示，不复制二进制或签名下载参数。来源身份仍以代码记录为准，不将昵称或自称作为认证。
- 恢复上下文标记为 `mnn-continuity-context`，是 DSH user-role 的历史数据，不是新增人类消息，不入 Inbox、不触发 Agent Turn。它没有独立的 system/developer 权限。
- 恢复内容来自同一 MNN 来源网络，不另建一份长期记忆；生成的上下文不得再被当作新的人类证据或用于循环强化。
- Self、权限和工具策略保持。正式写入前有完整 DSF 校验和 Provider 预算验证；原始事件仅追加，不回滚整个生产数据库。

## 正式结果与保留的失败

正式恢复了 24 轮、48 条近期对话，材料约 7,881 个官方词表 Token。原始事件前缀、所有系统段落、Self 摘要、Inbox 均保持，原生重开通过；重复应用未重复插入同一段上下文，压力低于恢复水位。

第一次操作后的校验报告因拿两次独立 `Session.create` 合成的 end-seed 比较而失败；启动门禁保持关闭。随后直接与维护前 DSF 中的真实持久化前缀比较，确认原始事件完全一致，修正验收对象后重验通过。失败报告、备份、修正后的报告均保留在本机，不覆盖。

本机审计：`.research/continuity-*/report.json`、`.research/continuity-prefix-audit.json`。公开源码不包含具体私人聊天原文；恢复正文只存于本机原 Session。

## 必须持续执行的回归标准

1. 维护后的上下文包含有来源的近期完整交流，不能仅检查数据库和身份摘要。
2. 同时保留用户与 Agent 的原话，区分参与者、外发与私密内容；不伪造新的经历。
3. Dreaming/隐私重建覆盖这段连续性资料，原始事件、工具配对、权限与 Self 不变。
4. 历史重建不被当作新指令或独立证据，不能引发自我确认循环。
5. 用持续话题、未完事项和真实用户复核评估连续性；不能只测文件生成，也不能只凭一条“更像她”的回答宣布修复成功。

目前自动回归与原会话数据验收通过；修复后语言与相处是否自然连续，仍待真实聊天验证。本次没有向正式渠道发送测试问候或要求模型模仿旧语气。
