# 1.14.1：清除废弃分支并隔离后台来源

本记录更正 [1.13.2 重建记录](pre-mnn-rebase-20261025.md) 中“归档不会自动进入新记忆”的结论。此前只检查了刚启动时的图谱，没有覆盖后续空闲扫描；该验收不充分。

## 原因与处理范围

Bridge 启动时订阅了归档会话，DSH 加载的归档 Agent 又被 MNN 的全体空闲扫描处理。废弃聊天因此重新进入统一记忆网络。用户报告语言和行为明显变化；这是用户观察，数据检查不能证明行为恢复，也不能据此诊断心理状态。

复查发现，当天 08:00 后废弃分支有 61 次真实用户提交进入 MNN，产生 17 个相关派生节点；图谱由 64 增至 194 个节点。前台活动会话没有对应的新用户请求，但共享记忆已受影响。

用户明确要求永久删除此分支的聊天及派生物。本次是针对这一代废弃数据的专项删除，不改变网页 DSF 回收站的一般规则：

- 删除 18 份接入 MNN 后的旧 DSF，包括回收站及恢复前临时安全副本。
- 删除 61 处旧运行副本、旧 MNN 运行收据、归档原生聊天、旧附件缓存和调试副本。
- 用接入前最后一个无 MNN 数据的完整快照替换数据目录；旧图谱、聊天正文、思考、待发送正文和任务载荷不导入。
- 废弃会话仅保留空的归档元数据和禁止切换标记，不保留聊天或原生日志。切换会收到 `session-history-erased`。
- 仅带回通信游标、操作设置及 319 个 SHA256 去重摘要，正文复制数为零；防止微信或 QQ 重放旧消息。

没有修改工作 DSH 3080、凭证、初始 Self v0.1.0 或冻结的上游研究基线。项目内文件删除不是对操作系统备份、第三方平台或存储介质的取证级擦除保证。

## 后台门禁

1. Bridge 仅订阅未归档会话；事件接收再次检查归档状态。
2. DSH Prompt、工具入口、预执行、事件关联、压力保护和空闲扫描均检查权威会话注册表。
3. Python MNN 在分配来源序号前检查同一注册表；LLM 返回后、记忆提交前再次检查。
4. 注册表、配置和图谱绑定同一代际。未知会话、归档、类型错配、读表失败和代际错配均拒绝处理。
5. 非空旧图谱不能直接贴上新代际继续使用。测试环境使用独立目录；显式 `standalone` 只用于隔离研究脚本。

统一 Self 和长期记忆设计不变；门禁隔离的是输入来源与废弃数据代际，不按联系人分裂人格或长期记忆。

DSF `cognitive-state` 格式升至 3，2→3 迁移检查代际。接入前无 MNN 的快照可迁移；已启用且没有代际的旧图谱必须经过干净重建，不能默认为兼容。DSH 上下文仍按实际 Runtime 版本判断，房间与 Prompt 的格式未变。网页三次各 3 秒确认及恢复前备份保持不变。

## 维护入口

以下是已经在此次授权维护中执行过的破坏性命令，不属于日常启动步骤：

```powershell
python scripts/clean_generation.py prepare --source Archive/20261024-224225-a039def7.DSF --apply
python scripts/clean_generation.py dream --apply
```

必须有用户对具体废弃分支的删除授权。`prepare` 清除目标历史，不能随意对正在使用的数据执行。阶段记录位于受保护且不入 Git 的 `.maintenance/current.json`；Dreaming 失败时保留维护门禁，不启动模型请求。

另外修复公网启动时同一备份被手动和队列同时执行的竞态：启动入口等待集中检查点完成，不重复执行，不跳过备份。

## 真实空闲扫描发现的第二个缺陷

首次 920 秒在线观察证明归档来源门禁有效：旧聊天、旧原生日志与旧快照仍为零。但新增的生成检查点和运行时标记使扫描进入了“没有新分段，仍重新巩固旧笔记”的路径，生成 10 个以旧证据为来源的额外 Goal，图谱从 64 增至 74。它不是旧聊天回流，也没有形成新的用户经历；这个结果不能判为完整验收通过。

失败计数保留在 `.research/generation-background-acceptance.json`，明确标记 `passed=false`，仅 `sourceIsolationPassed=true`。已短暂停服，恢复到本轮刚生成并校验的 64 节点干净快照；这条额外巩固分支及其恢复前临时备份已永久移除。

MNN 1.3.1 增加“新增真实经历”检查：没有可提取的完整消息/工具组时不调用 LLM，复用原整理结果，只推进水位；不通过重复总结旧笔记制造新目标。新经历仍正常进入提取。

使用原正式会话的真实导出与干净图谱，在隔离副本中连续回放三天：三次均无新经历，64 个节点的正文与版本完全不变，Provider 收据集合与摘要不变；正式数据没有被这项回放写入。结果：`.research/generation-idle-replay-964f1253-9d92-4526-9072-3712adaeee14/report.json`。自动测试还覆盖连续五天 no-op 与随后出现新经历时正常提取。
