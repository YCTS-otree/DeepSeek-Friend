# v1.4.2：普通回复进入私有笔记

## 原因与实际证据

2026-10-23 检查当前正式会话事件类型及发送队列：最近两轮正常完成，各有一条 assistant text，但均未调用 `weixin_send_message`，对应 emissions 数量为零。原 v1.4 的交互规则只允许消息工具向外发送，全部普通正文均被归为本机笔记，因此这些回复没有进入 iLink 队列。排查只输出类型、长度和数量，没有输出私有思考正文或凭证。

## 修改后的边界

- 微信入站和独立测试输入通过持久 `requestId` 绑定回复阶段；不根据正文关键词猜测收件人或权限。
- 首次回复阶段的普通 text 在原生 `agent/turn-stopping` 边界原子生成持久发送意图，随后才注入自主继续信号。关闭持续运行或选择休息时同样生效；完成事件提供恢复兜底。
- 使用消息工具时抑制这一阶段的自动正文，保留一轮多条消息，避免自动重复发送。
- `private_note({text})` 明确选择私下思考，抑制该阶段普通正文的自动发送；后续仍可通过消息工具明确对外发言。真实模型曾在私有笔记后附带收尾正文，回归发现后加入了这道保护。
- 原生 reasoning、内部闹钟和自主继续阶段的普通正文继续仅在本机保存。历史私有笔记不自动补发。
- 候选正文、阶段边界和固定发送意图 ID 持久化；重启与重复事件不会换 ID 重新投递。仍沿用原有 unknown 投递隔离，不宣称严格 Exactly Once。

原 Session、系统原稿、Self v0.1.0、记忆与双方聊天记录均保留；没有修改 DSH 核心或工作 DSH。新增表位于项目 interaction.sqlite；清空独立测试空间时一并清除其路由数据。

## 验证

Node 回归覆盖普通正文到 Mock 微信投递、双方聊天记录、边界发送后继续思考、显式发送去重、私有笔记后附带正文、闹钟与历史笔记不被提升、阶段重开后的幂等处理。完整回归及部署结果见 CHANGELOG v1.4.2。

另用独立端口 3098、独立 DSH home/测试记忆运行真实 DeepSeek-V41-Flash，验证普通正文自动生成发送意图、两次消息工具调用、私有笔记隔离、同轮续行、视觉与 Self 热更新。真实模型测试不向微信发送，也不在正式会话插入测试消息；手机端实际收信仍需用户确认。
