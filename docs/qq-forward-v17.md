# QQ 合并转发聊天记录 · v1.7.0

现有好友私聊发来的 OneBot `forward` 段现在会进入持久队列。Bridge 展开文字与图片后提交当前正式 DSH Session，引用作者姓名、QQ 号和时间仅作为未认证声明；真实发送者仍由外层 QQ 号与通讯录匹配。转发中自称 OTREE 不会获得可信身份或工具权限。

## 实际协议与恢复

本实现读取了 qq-bridge 的转发处理及 NapCat 4.18.41 的 `GetForwardMsg.ts`、`GetFriendMsgHistory.ts` 与消息转换源码。没有修改上游或复制其运行框架。

- 托管 OneBot 配置启用 `parseMultMsg: true`，将入站 `forward.data.content` 与原消息一并入库。后续使用该快照，避免重启后引用失效。
- 无内联内容时调用 `get_forward_msg({id})`，读取其 `messages` 数组，兼容原生 node 与 sender/message 结构。
- NapCat 的数字 ID 查询依赖进程内映射，重启后可能报告“消息已过期或者为内层消息，无法获取转发消息”。遇到拒绝时仅查询原发送者最近 20 条私聊，核对同一作者和相同转发 ID 后重试一次。找不到就明确失败，不扩大搜索范围。
- 展开与图片下载成功后保存快照；DSH 提交重试使用原 requestId、Session 和固定内容。
- 准备失败尚未提交 DSH 时结束该条并释放队列。人工恢复这类任务时，仅未被 DSH 接收过的回复路由可以重新打开；已接收、私有笔记和持续思考的路由不会因此开放。
- OneBot 拒绝原因经过凭证、URL 和控制字符脱敏后显示。投递结果不明仍保留 unknown，不盲目重发。

## 范围与限制

支持文字、引用作者声明、原生图片和有限嵌套转发。视频跳过，不下载。最多 64 个引用节点、1024 个片段、4 次转发查询，递归深度上限 4；文字使用 `bridge.maxTextChars` 的剩余空间，图片使用 `media.maxImages` 的剩余数量。超限会标明部分跳过。图片沿用现有 CDN、大小、超时和格式验证，再使用 Flash 的原生图片输入。

首版不支持群聊、语音、文件、任意历史搜索、完整原生付费表情或任意 URL 下载。历史记录过旧、资源过期、网关未能展开时仍可能失败；不会宣称严格 Exactly Once。
