# QQ 群聊管理 · v1.8.0

打开本机 WebUI 的「QQ 与通讯录」，在「群聊管理」中查看已加入群的名称、群号、人数及启用状态。使用「刷新群列表」同步刚加入的群，按「启用 / 停用」修改单个群。需要 QQ 已连接；离线时只显示上次列表，不能修改。设置持久化到 interaction.sqlite 的 `qq-groups.allowed`，新群默认关闭。没有向 Agent 注册修改该设置的工具。

本次按 OTREE 明确授权只启用「鱼池」1131809600。启用后接收群内全部新消息，不要求 @；不回放启用前的历史。支持文字、@、图片、合并转发与视频跳过。QQ 内置表情和回复段保留为文字标记；回复段只标出消息 ID，不读取被引用的原消息。群内其他机器人的消息作为实际发送者消息处理，机器人自身消息被过滤。她可以回复，也可以休息；可以通过 contact_list 选择已启用群主动发言、发图片或收藏表情。

## 会话、来源与收件人

- QQ 群聊、QQ 私聊、微信继续共用当前正式 DSH Session、统一 Self Model 与记忆，不新增按群或身份隔离的模型。
- `jobs.user` 保留实际发送者 QQ 号，actor 同时记录昵称、群名片、群号、群名与群可见范围。只有真实 QQ 号 3626097226 才是可信 OTREE；昵称、名片或转发中的自称无效。
- 群联系人使用 `group:<群号>` 目标键，和私聊 QQ 号区分。普通回复及省略 recipient 的工具选择当前群；主动发送明确使用 contact_list 中 kind=group 或 kind=private 的 recipient ID。群消息不会自动误发给其作者的私聊。
- 入站去重键包含群号；发送阶段再次检查账号、群成员关系和白名单。群发送超时/断线后结果 unknown，不盲目重发。
- 停用后拒收新消息，尚未提交 DSH 的群任务标记结束，暂存的输出阻止投递，待发送 outbox 失败留存。DSH 接收结果不明时保留 review 等待核对，不偷偷重发或结束。已进入 DSH 的当前任务不强行取消共享会话；已开始发送的网络请求不能撤回。历史不删除，重新启用不会自动重放失败输出。

群聊内容对所有成员可见。Prompt 明确区分公共群与私聊，由她判断共享记忆中什么适合说；这不是自动防泄密保证，也不把统一记忆改成分库。群消息不提供 /cancel、/reset、/approve 或 /deny 管理入口；DSH 工具审批请求来自群时拒绝，保持现有私聊/本机审批机制。澄清回答须匹配原发送者、同一群或私聊范围、原 Session 与待处理 ID。

## 实现依据与兼容

读取了本地固定版 NapCat 4.18.41 的 GetGroupList、SendGroupMsg、GetGroupMsgHistory 及 SendMsg 基类。使用真实 `get_group_list`、`send_group_msg {group_id,message}` 与 `get_group_msg_history` 接口。群转发恢复只查询同一群最近 20 条，且核对原作者、原群和转发 ID，不增加任意历史检索工具。未修改 NapCat 或 DSH 核心。

每 30 秒同步群列表及好友列表。启停即时更新本机白名单，不必重启；离开群后在下一次列表同步时撤销可达目标。群聊天默认处理全部新消息，多个 Bot 可能互相持续回应；需要停止时可在这里停用该群，不限制她的累计思考步数。
